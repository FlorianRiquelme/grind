# Grind — requirements

Round 4, after grilling. Round 3 designed a pipeline. The pipeline already exists, and
almost all of round 3 was superseded by reading `lfg`. What is left is smaller, better
defined, and unbuilt by anyone.

*(Superseded 2026-08-22: ADR-0015 retired the plugin and superseded ADR-0001 — the
pipeline-consumption premise ended, and Grind owns a ten-stage ladder of its own, resolving
[#92](https://github.com/FlorianRiquelme/grind/issues/92) and landed as PR #98.)*

See [`STRATEGY.md`](./STRATEGY.md) for who this is for and what it optimises,
[`CONTEXT.md`](./CONTEXT.md) for vocabulary, and [`docs/adr/`](./docs/adr/) for the twelve
accepted decisions that carry lock-in.

*(Corrected 2026-08-22: fifteen accepted decisions — ADR-0013 through ADR-0015 landed since
that count was written.)*

## What this is

**A queue, unattended dispatch, a supervisor, and a record around headless `lfg` runs.**

*(Corrected 2026-08-22 by ADR-0015: a queue, a supervisor and a record around headless runs of
Grind's **own stage ladder** — not headless `lfg` runs, which retired with the plugin.)*

It exists to make progress on work the human cannot sit with — meetings, travel, sleep,
anything. The input is a plan good enough to act on, which their day sessions already
produce. The output is an open PR and a room to talk about it in.

## What this is not

- **Not a pipeline.** `lfg` is the pipeline. See ADR-0001.
  *(Inverted 2026-08-22 by ADR-0015, resolving
  [#92](https://github.com/FlorianRiquelme/grind/issues/92): Grind owns the pipeline — its own
  ten-rung ladder — and this bullet has read backwards since. The never-gate ruling survives it
  unchanged; see ADR-0003.)*
- **Not a quality gate.** It hands off at an open PR and never asserts readiness. See
  ADR-0003.
- **Not nocturnal.** "Night" is one possible dispatch trigger. Nothing in the design is
  keyed to a time of day, and nothing should be named as if it were — which is why the
  project was renamed from `Nachtschicht` to `Grind`.
- **Not a place to try things.** Capabilities are proven in supervised sessions and
  promoted. See ADR-0002.
- **Not team infrastructure.** Single-user and opinionated on purpose; a colleague who wants
  it forks their own, which stays affordable because the shell over `lfg` is thin. See
  [`STRATEGY.md`](./STRATEGY.md).
- **Not a cockpit.** Still cut.

## The seam

The chain is `/ce-brainstorm` → enrich (grilling, ADRs, `CONTEXT.md` edits) → **seam** →
either `/ce-plan` and build it yourself, or **enqueue**.

At the seam there is a branch containing the enriched requirements artifact plus whatever
else the session wrote. That branch *is* the context — a Run reads all of it and treats it
as "context I need to fulfil the task." There is no declared artifact contract, and there
should not be one; a list would go stale the first time a session writes something new.

## A job

A labelled GitHub issue **in the repo the work happens in**. The cross-repo queue view is
`gh search issues --label <x> --assignee @me`, so a central queue would only duplicate
search while orphaning each issue from its code. The PR references it and closes it **on merge**,
which is the human's act — unless the Job is wider than its code, in which case the Run references
it without the keyword. Corrected 2026-08-13 resolving
[#14](https://github.com/FlorianRiquelme/grind/issues/14): neither Run closed its Job. Run 1's PR
named a different issue entirely and the Job was closed by hand; Run 2 wrote *"closes the code half
of #28"* as prose, deliberately and correctly, and #28 is open to this day.

*(Corrected 2026-08-15 resolving [#39](https://github.com/FlorianRiquelme/grind/issues/39):
not labelled — Grind applies no label and adds no taxonomy (ADR-0012). The queue view is
whatever the human's own tracker already gives them, so the `gh search --label` example above
is dead; the ruling it supported — no central cross-repo queue — survives it.)*

It carries: target repo, branch, **Handoff SHA**, the **Anchor artifact** path, the pinned
plugin version, and optionally a model and an **Intent** — one line on the work's nature.
Nothing else — the plan is generated by the Run, the verify entrypoint belongs to the repo, and
the settled decisions are already labelled KTDs inside the branch.

*(Corrected after the fact: a budget ceiling was carried here and ADR-0010 withdrew it. Spend is
recorded, never bounded.)*

The Handoff SHA does double duty: **context is everything behind it, reviewable output is
everything in front of it.** That single pin also makes `pre_existing` and the review base
fall out correctly, so the human's own ADRs are never reviewed as if the Run wrote them.

**Enqueue is one conversational step** with the human present. The one admission check
worth keeping is decomposability — a requirements artifact that cannot be broken into work
is the leading candidate for "this shape of job reliably fails unattended", and enqueue is
the only moment someone is there to notice.

## A run

`claude -p` invoking `lfg` against the job. The supervisor is **a script, not an agent** —
if the resilience layer is built from the thing that gets rate-limited, it loses its own
state exactly when that matters. Agent orchestration happens *inside* `lfg` stages, where a
death costs one stage rather than the job.

*(Corrected 2026-08-22 by ADR-0015, resolving
[#92](https://github.com/FlorianRiquelme/grind/issues/92): nothing invokes `lfg` any more. A Run
executes Grind's own ladder — ten stages, Plan through Ship, one Attempt per stage session with
its own authored skill text. Completion is supervisor observation of durable return files
(`stages/<name>.return.json`); advancement is the total pure function `rung::next`; a death
re-enters only the stage that died. Triage and DiffTriage are zero-token Rust passes that size
later stages into tiers T0–T3, escalation-only and fail-closed to T2.)*

What the supervisor owns:

- **Dispatch on demand.** Run-now is built first; a schedule is one line of cron
  afterwards. Building the scheduler first would make every debugging cycle wait for a tick.
- **Re-entry.** `lfg` returns `run_id`, `plan_checkpoint`, `unit_receipts` and
  `recovery_path`. A dead run re-enters at the stage it died on.
  *(Corrected 2026-08-02 by [docs/findings/0001](./docs/findings/0001-first-run.md): those fields
  are what `ce-work` returns **to** `lfg` at its step 2, internal to the run. Re-entry rides
  Claude Code session resume — the supervisor pins `--session-id` up front and re-enters with
  `--resume` — and stage is inferred from durable artifacts rather than read from a return value.)*
- **Limit handling, not limit monitoring.** No pre-flight quota check. On a rate-limit
  error: sleep long, re-enter the stage. Even a perfectly-informed supervisor would be wrong
  about what a stage costs.
- **Run state on local disk, gitignored.** Committing scheduler state would turn this
  repo's history into a run log. The durable human-facing record is the PR and the channel.

## Surfaces

| Surface | Carries | Owner |
|---|---|---|
| GitHub issue (target repo) | the job | human files, the merge closes |
| PR | the code, the review provenance, the narrative | Run opens |
| Buzz feature channel | the feature's whole history | Run seeds, human continues and archives |
| Local run state | checkpoints, structured returns | supervisor, gitignored |

The table said **Draft PR** until 2026-08-13. `lfg` opened a normal PR on both Runs and has no
opinion Grind can rely on; #14 ruled the PR normal, because a draft cannot be merged — a
gate-shaped affordance Grind does not own (ADR-0003) — and because a repo whose workflows filter
drafts would make the CI observation inside #9's completion test unobservable.

*(Retired 2026-08-13 resolving [#15](https://github.com/FlorianRiquelme/grind/issues/15): the
term retires with the channel. Nothing reaches the human — the supervisor's terminal-state
comment on the Job issue is the one surface that leaves the host — and the human looks rather
than being reached. The gap between the dispatch comment and the terminal one stays held as
fog on [#5](https://github.com/FlorianRiquelme/grind/issues/5), revisit once a Run has actually
hurt there.)*

**Buzz** is the right shape for the human surface, and `buzz-cli` is agent-first
(JSON in / JSON out, ACP harness covering Claude Code), so the human and agent surfaces are
one substrate rather than two that drift. "Branch as room" is the project's own stated
design. Two caveats: push notifications are not built, and mobile clients are still being
wired up — so the phone case is the least-ready part today, and the relay is self-hosted.
Because dispatch never depends on the relay, a relay outage cannot stop a run.

**No cross-run digest in leg 1.** Channel presence already does what the digest's "needs
you" section was for, and the human moves and archives channels by hand. If a week of runs
shows a cross-run view is wanted, it is an hour's work against the local run state — and a
projection is cheap to replace, which is why the structured record matters and the rendering
does not.

## Constraints accepted deliberately

- **Session and weekly limits are the scarce resource, not wall-clock.** Moving work to the
  night never created capacity; it only avoided contention inside a 5-hour window. Dispatch
  is therefore **human-managed** for now: the human dispatches when they can bear the limit,
  and runs do not monitor it. Giving the runner its own credentials is the right long-term
  answer and is deliberately deferred.
  *(Corrected resolving [#11](https://github.com/FlorianRiquelme/grind/issues/11) 2026-08-03 and
  [#23](https://github.com/FlorianRiquelme/grind/issues/23) 2026-08-09: refined plans are the
  scarce input — they trickle in slower than the weekly limit refills — and dispatch is
  human-managed because Grind never selects a Job, not because the human rations spend. Spend is
  recorded, never bounded (ADR-0010).)*
- **Inherited `lfg` opinions.** No `depth:full` on its review step, no extra lens, no
  control of its fix-round budget. All of these are promotion candidates, not PoC work.

## Cut from round 3, and why

| Round 3 | Why it went |
|---|---|
| The whole stage pipeline, integrity rules, loop bounds | `lfg` already implements all of it, more carefully |
| Immutable verify command hashed at enqueue | `ce-work`'s `verification_evidence` contract covers the real risk; a generic repo `verify` entrypoint is good hygiene but not load-bearing here |
| Orchestrator-owned severity, retirement, freshness filters | Superseded — `lfg` applies eligible findings and files the rest as durable residuals |
| Grind as a Tier-4 calibration harvester | Neat, not true. A Grind job supplies no known-clean cases (the metric the Phase-2 flip is set against), cannot observe recall, and its diffs are pre-conditioned to comply because the implementer had the card. Dropped rather than downgraded — it is the guidelines repo's question to answer when it gets there |
| Gating on guideline findings | Unnecessary; Grind never gates. See ADR-0003 |
| Co-designing with `svo-engineering-guidelines` | Both are PoCs. Coupling two PoCs slows both. It plugs in when it is ready, on its own schedule |
| Per-night digest, cockpit, HTML rendering | Channels do the surfacing |

because `lfg` already owned it. It arrived anyway as its own ladder once lfg's shape cost proved
real ([docs/findings/0004](./docs/findings/0004-fourth-run.md)); the rows stand as written.)*

## Still open

1. **Learnings across runs.** Correctly deferred — it is downstream of having runs to read.
   The highest-value class remains "this shape of job reliably fails unattended", which
   tightens enqueue rather than implementation.
   Run 2 produced the first unprompted instances: the target repo's own ledger convention
   caught a signer failure and a shell-quoting trap (`docs/findings/0002-second-run.md`).
2. **First job shape.** Boring, verifiable, and with enough substance that the review step
   has real work to do.
   *(Spent 2026-08-21: three Jobs have run — snapper#21, snapper#28 with real design content,
   and grind#80 dispatched at Grind itself.)*
3. **Unverified mechanics**, none blocking: whether `--disallowedTools`
   denials are inherited by subagents — settled 2026-08-02, they are, and `bypassPermissions` does
   not override them ([docs/findings/0001](./docs/findings/0001-first-run.md)); whether an artifact
   can be published from a headless run at all — partially answered, MCP tools resolve inside a
   headless Run (same document); whether `claudefuel`'s per-profile usage cache is readable by a
   script — still unverified, and
   [#7](https://github.com/FlorianRiquelme/grind/issues/7) records that no scriptable budget check
   exists.
